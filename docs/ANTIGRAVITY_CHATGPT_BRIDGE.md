# Подключение ChatGPT к облачному Antigravity для Smachno Studio

## Что получится

Ты пишешь задачу в ChatGPT. Я создаю GitHub Issue в репозитории Smachno Studio с меткой `agent-run`. GitHub Actions запускает Google-managed Antigravity Agent через Gemini Interactions API. Агент работает в удалённой Linux-среде Google, поэтому твой компьютер может быть выключен. По завершении агент должен открыть Pull Request; сайт не публикуется автоматически.

Схема:

```
ChatGPT (GitHub-инструменты)
        │ создаёт Issue с меткой agent-run
        ▼
GitHub Actions (облачный запуск)
        │ Gemini API + задание + ограниченные секреты
        ▼
Google Antigravity managed agent (remote sandbox)
        │ изменяет отдельную ветку и открывает Pull Request
        ▼
GitHub Pull Request → проверка Сергеем → отдельное решение о слиянии
```

Это намеренно не локальный MCP-сервер: он не зависит от включённого ПК и не требует открывать домашний компьютер в интернет.

## Важные различия и стоимость

- Antigravity Remote Agents доступны для личных Google AI Pro/Ultra аккаунтов по мере включения функции. Это позволяет запускать и продолжать удалённые сессии через antigravity.google.com без постоянно включённого компьютера.
- Этот автоматический запуск из GitHub Actions использует **Gemini Interactions API / Antigravity Agent**, а не локальную сессию Antigravity в IDE. Он получает инструкции из репозитория и задачи, но не наследует автоматически историю локального агента.
- Использование Interactions API тарифицируется отдельно по токенам Gemini API; подписка Google AI Pro не является API-биллингом. В этой заготовке выбран Gemini 4 Argon и ограничение 50 000 токенов на задачу.
- По опубликованному тарифу Gemini 4 Argon стандартные токены стоят $2 за 1 млн входных и $10 за 1 млн выходных до 30 ноября 2026 года; с 1 декабря 2026 года — $4 и $20 соответственно. При лимите 50 000 токенов теоретическая верхняя граница только по токенам — около $0.50 до 30 ноября и $1 после 1 декабря, если все токены тарифицируются как выходные. Реальная сумма зависит от доли входных/выходных/мышления и инструментов.
- Вычислительная среда managed agent на время preview не тарифицируется отдельно, но токены тарифицируются.
- ChatGPT Go не требует перехода на Business для предложенного варианта: запуск инициируется через уже подключённый GitHub-инструмент, а не через custom MCP write connector.

## Что нужно один раз настроить

### 1. Gemini API key

1. Открой Google AI Studio: https://aistudio.google.com/api-keys
2. Создай API key для проекта Gemini API.
3. Не отправляй ключ в ChatGPT и не вставляй его в файлы репозитория.
4. Добавь ключ в GitHub repository secrets с именем `GEMINI_API_KEY`.

Путь: GitHub → SergeyKrasa/smachno-studio → Settings → Secrets and variables → Actions → New repository secret.

### 2. Отдельный GitHub fine-grained token для агента

Создай Fine-grained personal access token только для репозитория `SergeyKrasa/smachno-studio`.

Минимальные права:
- Metadata: Read-only (обязательное).
- Contents: Read and write (создание ветки и отправка изменений).
- Pull requests: Read and write (создание Pull Request).

Не выдавай доступ ко всем репозиториям и не используй классический токен с широкими правами.

Добавь его в GitHub repository secrets с именем `ANTIGRAVITY_GITHUB_PAT`.

Токен используется только в сетевых заголовках Google egress proxy для `github.com` и `api.github.com`; он не включается в текст задания и не передаётся модели как обычный текст. Не печатай его в журналах.

### 3. Метка запуска

В GitHub создай метку Issue с точным названием:

`agent-run`

Workflow принимает задания только если:
- Issue создан Сергеем (GitHub login `SergeyKrasa`);
- метку `agent-run` добавил Сергей;
- секреты настроены.

### 4. Защита основной ветки

Рекомендуется включить защиту ветки `main`: изменения должны приходить через Pull Request. Агент не должен сливать PR или публиковать сайт. Перед слиянием Сергей проверяет preview, изменения и тесты.

## Как запускать задачу из ChatGPT

После установки workflow в `main` достаточно написать в ChatGPT, например:

> Terra, поручай агенту добавить на сайт отдельную страницу Chef's Challenge и рекламный блок на главной. Работай от ветки chef-challenge-prototype и открой Pull Request.

Я создаю Issue с меткой `agent-run`. Workflow запускает облачного агента, после чего в Issue появляется отчёт и ссылка на Pull Request.

Пока задача выполняется, локальный компьютер не требуется. Google Agent API и GitHub Actions работают в облаке.

## Что workflow делает и чего не делает

Делает:
- Проверяет автора Issue и отправителя события.
- Запускает Antigravity Agent в удалённой среде.
- Подключает публичный репозиторий Smachno Studio.
- Даёт узкий GitHub PAT только для этого репозитория.
- Ограничивает работу 50 000 токенами и 55 минутами ожидания workflow.
- Публикует отчёт в Issue.

Не делает:
- Не сливает Pull Request.
- Не изменяет автоматически `main`.
- Не публикует сайт.
- Не срабатывает на Issues от посторонних пользователей.
- Не выдаёт локальные счётчики за общую статистику.

## Статус заготовки

Этот файл и workflow сначала помещаются в отдельную ветку `chatgpt-antigravity-bridge`. Они не запускаются на основном сайте, пока Сергей не проверит изменения и отдельно не разрешит слияние в `main`.

До установки обоих GitHub secrets и метки `agent-run` автоматический запуск не заработает.
